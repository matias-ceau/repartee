# Repartee Mirror Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn Repartee into a mirror of its owner: ingest personal material, distil a readable self-model with evidence, and run a terminal agent that answers and drafts in the owner's voice.

**Architecture:** Four layers (ingest, store, self-model with a distill pipeline, mirror runtime with a voice subsystem) over shared pydantic types. All personal data lives in a private "home" directory outside this repository. Every LLM call goes through one small async protocol with a scripted fake for tests.

**Tech Stack:** Python 3.12+, uv, pydantic 2, SQLite (FTS5), numpy, fastembed, anthropic SDK, click, Textual, pytest, ruff.

**Spec:** `docs/superpowers/specs/2026-11-14-mirror-design.md` — read it first; this plan only adds file ownership, names and signatures.

## Global Constraints

- Python `>=3.12`. Run everything with the project virtualenv: `.venv/bin/python -m pytest <path> -q`, `.venv/bin/ruff check <path>`.
- Shared contracts already exist and are **read-only** for every task: `src/repartee/schema.py`, `config.py`, `home.py`, `llm/base.py`, `pyproject.toml`. If one needs to change, say so in your report; do not edit it.
- A task touches only the files it lists. Several tasks run at the same time in the same working tree.
- No `git` command that changes state (`add`, `commit`, `stash`, `checkout`, `reset`, `restore`). The coordinator commits.
- No new dependencies. Available: anthropic, click, fastembed, numpy, pydantic, pyyaml, regex, rich, textual, pytest, pytest-asyncio.
- Tests need no network, no API key, no real embedding model. Anything that does is marked `@pytest.mark.live` (skipped by default).
- No personal data anywhere. Fixtures are invented; do not model them on a real person.
- Text handling is Unicode-aware (use the `regex` module for `\p{...}` classes) and must not assume a language.
- For each behaviour: write the failing test, run it and see it fail, write the code, run it and see it pass. Finish with the task's whole test directory and `ruff check` clean.
- Public functions and classes get a one-line docstring. Line length 100. No abstraction without a second user.
- Where the code of an earlier task differs from this plan, the code is the source of truth.

## Review Focus

Failure modes the spec implies that are most likely to bite a real owner. Each is pinned by a test in the task named.

1. A WhatsApp export in a date or language variant the parser has not seen: it must not crash or silently mis-date; unplaceable lines are counted in the report (Task 2).
2. The owner edits a self-model page by hand (CRLF endings, nested lists, list items in Notes, a deleted claim): nothing they wrote is lost or rewritten, and a load-save cycle is byte-identical (Task 5).
3. No API key or no network: every command that needs no model still works; the ones that do fail with one line saying how to fix it, not a stack trace (Tasks 4, 11).
4. The embedding model cannot be loaded: search falls back to keyword only and `status` says so (Tasks 3, 11).
5. The home is placed inside the code checkout, or a personal file is staged for commit: refused with a clear message (Task 7).

Decisions:
- `ingest_home` = every configured source (`root` is `home.source_path(source)`, `skip_under=home.root` for vault and writing sources that live outside the home) plus the home's `interviews/` (source `interviews`, kind `interview`), `conversations/` (source `conversations`, kind `mirror`) and `drafts/` (source `drafts`, kind `draft`). Missing folders are not an error.
- Ids: WhatsApp `make_item_id("wa", chat, timestamp.isoformat(), author, text, ordinal_among_identical)`. Markdown `make_item_id(prefix, relative_path, heading_trail, ordinal)` — location, not text. Transcripts `make_item_id(prefix, relative_path, turn_index)`.
- `holdout = is_holdout(id, percent)` only for owner items of kind message, essay, journal, note.
- WhatsApp: both export families, 12h/24h (including narrow no-break space before AM/PM), 2/4-digit years, `.`/`/`/`-` date separators, direction marks, multi-line messages, zip and folder exports. Day/month order inferred per file (any first field > 12 means day-first; any second field > 12 means month-first; otherwise day-first), forced by `source.options["date_order"]` in `{"dmy","mdy","ymd"}`. System lines, media placeholders, deleted and edited markers come from one table covering at least English, French, Spanish, German, Italian, Portuguese. Media placeholders and system lines produce no item; a deleted message produces no item; the edited marker is stripped and `meta["edited"]=True`. Chat name = file stem with the `WhatsApp Chat with ` / `WhatsApp Chat - ` / `Discussion WhatsApp avec ` prefix removed, or the folder name for `_chat.txt`.
- Markdown: one item per heading section (text before the first heading is its own section); a file with no headings is one item. Journal: one item per file, or per dated heading in a single-file journal. Frontmatter `kind:` beats `source.kinds` globs beats default (`note` for vault, `essay` for writing). Timestamp: frontmatter `date`/`created`, else a `YYYY-MM-DD` in the file name. `meta` gets `tags`, `links` (wikilink targets), `path`. Author is the owner name, `is_self=True`. `exclude` globs and anything under `skip_under` are skipped.
- Internal transcript format (written by Task 10, read here):

```markdown
---
kind: interview            # or mirror
date: 2026-11-14T10:32:00
mode: interview            # chat | draft | interview | review
title: Childhood
---
**mirror:** Where did you grow up?

**me:** In Nantes, until I was eleven.
Then we moved.

**mirror:** ...
```

  One item per turn. `**me:**` → `is_self=True`, author = owner name. `**mirror:**` → `is_self=False`, author `mirror`.
- Internal draft format (written by Task 9, read here): frontmatter `kind: draft`, `date`, `register_name`, `recipient`, `intent`, `accepted`; body sections `## Mirror` and `## Final`. Only `## Final` becomes items (one per blank-line-separated block), kind `draft`, `is_self=True`, `meta` carrying `register_name` and `recipient`.
- Tastes: CSV (header-sniffed columns such as artist/track/album/title/author/plays/year/played_at), JSON arrays of listening records (aggregate to per-artist play counts per year), markdown lists. Output: `taste` items of at most 50 lines of normalized text each, `is_self=True`.
- Language: a stopword-profile detector for at least en, fr, es, de, it, pt, nl; `None` under a confidence threshold. In `ingest_source`, an item with no detected language inherits the most common language of its neighbours in the same container (window of 20).
- Chunking: chats split on a gap ≥ `chat_gap_hours` or when `estimate_tokens` passes `chat_max_tokens`; rendered `[YYYY-MM-DD HH:MM] Author: text`. Notes and essays: consecutive sections of one file merged up to `note_target_tokens`, a longer section split on paragraph boundaries. Journal, interview, mirror, draft, taste, medical: one chunk per container entry, split when over twice the target. `self_text` = owner items' text joined by newlines. `participants` = distinct authors in order of first appearance. Chunk id = `make_chunk_id(item_ids)`. `lang` = most common item language.

```python
# store/embed.py
class EmbedderUnavailable(Exception): ...
class Embedder(Protocol):
    name: str
    dim: int
    def embed(self, texts: Sequence[str]) -> np.ndarray: ...   # float32 [n, dim], L2-normalized
class HashEmbedder:            # deterministic character n-gram hashing; __init__(dim: int = 256)
class FastEmbedEmbedder:       # __init__(model_name: str); loads lazily; raises EmbedderUnavailable
def get_embedder(config: EmbeddingConfig) -> Embedder | None   # None when disabled or unavailable

# store/corpus.py
class SyncStats(BaseModel):
    added: int = 0
    updated: int = 0
    removed: int = 0
    unchanged: int = 0
    remapped: dict[str, str] = {}    # vanished item id -> new id with identical text

class Corpus:
    def __init__(self, path: Path | str, embedder: Embedder | None = None): ...
    embedder_name: str | None
    def sync_items(self, items: Iterable[Item]) -> SyncStats: ...      # the whole corpus each time
    def sync_chunks(self, chunks: Iterable[Chunk]) -> SyncStats: ...   # embeds only new/changed
    def sync_reply_pairs(self, pairs: Iterable[ReplyPair]) -> None: ...
    def sync_claims(self, claims: Iterable[Claim]) -> None: ...
    def get_item(self, item_id: str) -> Item | None: ...
    def get_items(self, item_ids: Iterable[str]) -> list[Item]: ...
    def existing_item_ids(self, item_ids: Iterable[str]) -> set[str]: ...
    def get_chunk(self, chunk_id: str) -> Chunk | None: ...
    def chunk_for_item(self, item_id: str) -> Chunk | None: ...
    def iter_items(self, filters: SearchFilters | None = None, *,
                   holdout: bool | None = None) -> Iterator[Item]: ...
    def iter_chunks(self, filters: SearchFilters | None = None) -> Iterator[Chunk]: ...
    def neighbors(self, chunk_id: str, before: int = 1, after: int = 1) -> list[Chunk]: ...
    def search(self, query: str, filters: SearchFilters | None = None, k: int = 10,
               mode: Literal["hybrid", "keyword", "semantic"] = "hybrid") -> list[SearchHit]: ...
    def search_claims(self, query: str, kind: PageKind | None = None,
                      k: int = 10) -> list[tuple[Claim, float]]: ...
    def search_reply_pairs(self, context: str, recipient: str | None = None,
                           k: int = 5) -> list[ReplyPair]: ...
    def chunk_hash(self, chunk_id: str) -> str | None: ...             # stable_hash of chunk text
    def stats(self) -> dict[str, Any]: ...
    def close(self) -> None: ...
```

Decisions:
- One SQLite file, WAL mode. FTS5 with `unicode61 remove_diacritics 2`. User queries are escaped so punctuation and FTS operators in a query can never raise.
- Sync methods take the complete current set and diff by id and text hash: unknown ids are added, changed text updated (and re-embedded), ids not present removed. `remapped` pairs each removed id with an added id of the same source and identical text (one to one).
- Embeddings stored as float32 blobs in a table keyed by (table, id, embedder name); loaded into one numpy matrix lazily and invalidated on sync. Changing the embedder re-embeds.
- Hybrid = reciprocal rank fusion (k=60) of FTS BM25 rank and cosine rank. With no embedder, `hybrid` and `semantic` both behave as `keyword`. `SearchHit.snippet` is a window of about 240 characters around the best match.
- Filters: `participant` matches `Chunk.participants` case-insensitively and by substring of a name token; `author="self"` keeps chunks with non-empty `self_text`; `after`/`before` compare with chunk `start`/`end`.
- `neighbors` returns chunks of the same container ordered by `start`, including the chunk itself.
- `search_claims` skips rejected claims. `search_reply_pairs` embeds `context`; without an embedder it uses FTS over pair contexts.
- `stats()` keys: `items`, `chunks`, `by_source`, `by_kind`, `self_items`, `embedded_chunks`, `embedder`, `first`, `last`, `claims`, `reply_pairs`.

Decisions:
- `AnthropicClient`: model and effort from the request's tier. Thinking parameter omitted. No sampling parameters. `output_schema` goes through structured outputs and comes back as `parsed` (validated instance). Tools are passed with `strict` and tool choice left on auto. System blocks become text blocks, `cache_control` on those with `cache=True`. Assistant `Message.raw` is replayed verbatim; user tool results are sent together in one user message. `stop_reason` is checked on every response; a refusal after fallback raises `LLMRefusal`. Server-side refusal fallback is enabled the way the skill prescribes for this model. SDK errors are mapped: authentication and connection problems to `LLMUnavailable`, the rest to `LLMError`, keeping the SDK's own retry behaviour. `stream` uses the SDK streaming helper and yields `TextDelta`, then `ToolCallEvent`s, then `Done`. `complete_many(batch=True)` uses the Message Batches API (poll until ended, map results by custom id, failures returned in place); `batch=False` uses the base implementation.
- `FakeLLM`: rules registered with `on` are tried first (most recently added first; a string matches `request.purpose`), then the queue; with neither it raises `AssertionError` naming the purpose. A `str` reply becomes text; a `BaseModel` becomes `parsed` (and its JSON as text); a `list[ToolCall]` becomes a `tool_use` stop; an `Exception` is raised. `stream` splits text into several deltas.
- `CachedLLM` caches `complete` only, one JSON file per key under `directory`; key = hash of (model for the tier, purpose, system texts, messages, tool specs, output schema JSON). Responses with a `parsed` value are re-validated from JSON with the request's schema on a hit. Errors are not cached. `stream` passes through.
- `PRICES` copied from the skill's current model table; unknown model → cost 0.0. Batch halves the price.

```python
class SelfModel:
```

Decisions:
- A page is modelled as its original lines. Claims are single-line list items (`- ` or `* `) ending in ` ^c-xxxxxxxx`, directly under a level-2 heading. Nested list items, numbered lists and anything else are owner text and never touched. Line endings (LF or CRLF) and a missing final newline are preserved.
- `new_page` writes frontmatter (`kind`, `title`, `aliases`, `updated`), `# title`, the kind's `PIPELINE_SECTIONS` as empty `## ` headings, and `## Notes`. `core` gets `## Pinned` and `## Generated` with the markers `<!-- repartee:generated:start -->` / `<!-- repartee:generated:end -->`. Voice cards get `## Generated` with the same markers and `## Notes`.
- Sidecar `self/.claims/<page key>.json`: `{"claims": {id: {...Claim fields except id/page/section/text, plus "text_hash"}}, "rejected": [{"text", "norm_hash", "evidence", "rejected_at"}]}`, keys sorted, indent 1.
- `load()` reconciliation follows the table in spec §10.3. A list item without id in a pipeline section gets an id (the page file is rewritten with it on `save`). Owner-written items in other sections are left alone and are not claims. Ids are unique across the model; an id found on a different page than its sidecar says is a move.
- `apply` validation, in order: unknown claim id; claim is `confirmed` or `rejected` (refused for `revise` and `supersede`; `support` is allowed on `confirmed`); section not in `PIPELINE_SECTIONS` for the page kind; page missing (an `add` to a missing page is refused, pages come from `create_page`); empty evidence for `add`/`supersede`; evidence ids unknown to `existing_evidence` when given (unknown ids are dropped; refused if none remain); text whose normalized form matches a rejected claim on that page, or an existing live claim on that page (duplicate → refused with reason `duplicate`). `supersede` sets `valid_to` on the old claim, moves its line to `Earlier`, adds the new claim to the old claim's section. `support` adds evidence and raises confidence: `c + (1 - c) * 0.25` per new independent evidence id, capped at 0.95. `question` appends to `open-questions.md` unless the same normalized text is already there.
- `create_page` for an existing key is a no-op success. The catch-all page for a kind is `page_path(kind, CATCH_ALL_SLUG)`.
- `open-questions.md`: `- [ ] text (page: people/ana-ruiz) ^q-xxxxxxxx`; resolved ones `- [x]`.
- `resolve` close match: casefolded equality on slug/title/alias first, then `difflib` ratio ≥ 0.88 against titles and aliases of that kind.
- `edit`/`confirm`/`reject` are the owner's actions (review mode): `edit` sets text, status `confirmed`, origin `user`.

Decisions:
- Tools and arguments are exactly the table in spec §13 (`search_self`, `read_page`, `search_memory`, `read_memory`, `get_voice`, `similar_replies`, `note_gap`). Each returns bounded text (about 2,000 characters per call), with ids so the model can chain calls. `get_voice` is only offered when a `voice` lookup is provided; Task 11 wires it. Unknown tool or bad arguments → `ToolOutcome(is_error=True)`, never an exception.
- System prompt = mode instructions (grounding rules from spec §13 verbatim in substance) + `model.core_text()`, as two `SystemBlock`s, the second with `cache=True`. The current date is put in the first user turn, never in the system prompt.
- Loop: `llm.stream` with tier `chat`, purpose `chat` (`interview` in interview mode); execute all tool calls of a turn, append one user message with all results, continue until a turn has no tool calls; at most 8 tool rounds, then a final request without tools. Assistant messages are appended from `Done.response.message` so raw content is replayed.
- In `draft` mode, `send("@ana tell her I can't make it Friday")` parses an optional leading `@recipient` and optional `#register`, calls the drafter, yields `DraftEvent` then `DoneEvent`; a following plain message ("shorter", "more direct") re-drafts with the instruction appended to the intent and the previous variant as context. `accept_draft` records through the drafter and returns the path. Without a drafter, draft mode says drafting is not set up.
- Sessions: `chat` and `draft` modes log to `home.conversations_dir`, `interview` to `home.interviews_dir`, file name `<YYYY-MM-DD>-<HHMMSS>-<slug>.md`, in the transcript format given in Task 2. A draft's text is logged as a mirror turn.
- Interview: questions come from `model.questions()` (filtered by topic when given), else the model proposes them from thin areas; one question per turn; the mirror may follow up at most twice before moving on; `/skip` moves on. `finish` writes the transcript, calls `on_finish(path)` (which ingests and distils; wired by Task 11) to get the claim ids produced, resolves the questions that were answered, and returns them for the closing review.
- `ReviewQueue` orders unconfirmed claims by confidence ascending; a queue built with `claim_ids` is limited to those.
